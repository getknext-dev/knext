Pin the whole spec of each zone function your app binds, not only its image. Add `specDigest` to an entry in `backends` in `knext.config.ts`, for example `backends: [{ name: "user-profile", specDigest: "sha256:<64 hex digits>" }]`; `knext deploy function` now prints the exact entry to paste. The digest covers the function's image, `env`, `envFrom` and `volumes`. The operator re-computes it from the `BackendService` on the cluster and runs the function only while it matches. Any other spec is refused: the function reports `Ready=False` with the reason `BindingSpecMismatch`, the message names both digests, its Knative Service is removed, and nothing is mounted into it. So with a spec pin, someone who can only write the function's `BackendService` can no longer keep the pinned image and add `NODE_OPTIONS`, an `envFrom` or a volume to run their own code with your zone's database Secret mounted. What remains: the contents of the Secrets and ConfigMaps the spec names are not part of the digest, and neither are `port`, `protoVersion`, scaling, resources or `imagePullSecrets`, which you can still change without touching the zone. The order of the entries in `env`, `envFrom` and `volumes` counts. Without a spec pin, with only an image pin or none, nothing changes: grant `update`, `patch` and `create` on `backendservices` only to people who may already read your zone's database Secret. The `image` pin keeps working beside the new field, as the weaker option. If you write `env`, `envFrom` or `volumes` into the `BackendService` by hand, the digest `knext deploy function` printed does not cover them; review the spec, then pin the digest the operator reports in the refusal. The digest is never written into your zone's pods, so changing it does not roll a zone revision. When you change the function, update the pin in the same step; between the two writes the function is refused and runs again once they agree. The field is a new part of the NextApp resource, so install the operator release that includes it first, then upgrade the CLI: a CLI that sends `specDigest` to an older operator fails the deploy preflight, which names the field.
