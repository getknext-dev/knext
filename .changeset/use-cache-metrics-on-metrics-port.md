The app's Prometheus endpoint on port `9464` now serves the `'use cache'` store's counter, `knext_use_cache_events_total`, labelled `event` (`hit`, `miss`, `stored`, `oversize`, `dropped`, `prune_error` and the rest), so skipped oversize entries, Redis outages and failed clean-ups are visible. It reaches the port through the same local metrics listener as the CDN counters; apps generated by `knext create` already start it. A Redis that refuses scripts now logs the failed clean-up of old invalidation timestamps once until a clean-up succeeds, instead of about once every 30 seconds.
