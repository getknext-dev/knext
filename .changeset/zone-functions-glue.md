Zone functions (Beta): `knext generate` now also writes the code your pages call. A side-effect-free read becomes a server-only cached query, keyed on the signed-in user, the contract version the function serves and the request, so two users never share an entry. Any other unary RPC becomes a Server Action that refreshes those cached reads, and a server-streaming RPC becomes an async generator for Server Components and route handlers. Every RPC must state who may call it, with `option (knext.v1.auth) = AUTH_USER` or, on a read only, `AUTH_PUBLIC`. Every generated call runs your `authorize()` hook first (`"authorize"` in `knext.grpc.json`; `knext add function` scaffolds one that refuses every call until you write it). `knext generate` refuses an RPC with no auth option, a public write, client-streaming and bidirectional RPCs, and a missing `authorize()` hook. Calls use h2c on a Node server and HTTP/1.1 on a Bun server by default, override it per function with `<NAME>_SERVICE_HTTP_VERSION`, and log the transport once per function. The served contract version is read from `<NAME>_SERVICE_PROTO_VERSION`, and a call is refused when it is unset or older than the zone's. Until the per-call identity token is available, every generated call is refused before it leaves the zone.
