Pin the image of each zone function your app binds. Add `image` to an entry in `backends` in `knext.config.ts`, for example `backends: [{ name: "user-profile", image: "@sha256:<64 hex digits>" }]`; `knext deploy function` now prints the exact entry to paste. With a pin the operator runs the function only while its `BackendService` image carries exactly that digest. Any other image is refused: the function reports `Ready=False` with the reason `BindingImageMismatch`, its Knative Service is removed, and nothing is mounted into it, so changing the `BackendService` alone can no longer send your zone's database Secret or your users' tokens to an image you did not agree to. Without a pin nothing changes: any image the `BackendService` names is bound, which means anyone allowed to update `backendservices` can change what runs with your zone's database Secret, so grant that permission only together with read access to that Secret. The pin is never written into your zone's pods, so deploying a new function image does not roll a zone revision. When you deploy a new function image, update the pin in the same step; between the two writes the function is refused and runs again once they agree. The field is a new part of the NextApp resource, so install the operator release that includes it first, then upgrade the CLI: a CLI that sends `image` to an older operator is stopped by the deploy preflight, which names the field.
