Zone signing-key rotation now waits 120 seconds by default (it was 90) before a zone starts signing with a new key, and the operator refuses `--zone-signing-key-propagation-bound` below 90 seconds (it was 60). A running function only sees the new public key once the kubelet has rewritten the mounted ConfigMap, which on a default kubelet can take 90 seconds (its 60 second sync period stretched by up to half again). On GitHub-hosted test nodes that took up to about 85 seconds, so the old 90 second default left a few seconds of margin and the old 60 second minimum was below what was measured. A function whose refresh landed after the switch would refuse the zone's calls with no sign in the operator. The default is that worst case plus 30 seconds, and a rotation takes 30 seconds longer. If you start the operator with a bound between 90 seconds and 2 minutes it still rotates, and the `ZoneSigningKey` condition on the zone now says the bound is below the default while a rotation is propagating or in its overlap. If you pass a bound under 90 seconds, the operator now refuses to start: raise it to at least `90s`, or remove the flag to take the new default.
