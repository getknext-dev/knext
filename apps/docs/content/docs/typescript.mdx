A `knext create`-scaffolded app pins `typescript@^5.9.3`. This page explains why that's the
default, what TypeScript 7 actually gets you, and how to opt in if you want it anyway.

## The default: TypeScript 5.9.x

TypeScript 7 is the new Go-native compiler, and it's real: a scaffolded app builds and runs its
tests cleanly under it on either build target, and Next.js's own typecheck step during `next
build` works correctly under TS7 — it needs none of the classic TypeScript compiler API.

It is not the default anyway, because TS7 breaks tooling **around** your app that a normal Next.js
project relies on:

- **`typescript-eslint` does not support TypeScript 7.** Its peer dependency range caps at
  `typescript<6.1.0`, so `eslint-config-next` — which every scaffolded app ships — fails outright
  under TS7. There is no supported way to lint a TS7 project with the tooling knext scaffolds today.
- **TypeScript 7 ships no `tsserver.js`.** That's the language server VS Code, other editors, and
  Next's own `next.config.ts`-aware tooling use for "workspace TypeScript" — inline errors,
  autocomplete, go-to-definition. None of that works under TS7 yet.

Both of those are real breakage for a normal day-to-day workflow, not edge cases — so the
scaffold default stays on 5.9.x until the surrounding ecosystem catches up.

## Opting in to TypeScript 7

If you don't need eslint or editor TypeScript support (for example, a CI-only build, or you're
comfortable running without either until the ecosystem catches up), you can switch a scaffolded
app to TS7 yourself:

```json title="package.json"
{
  "devDependencies": {
-   "typescript": "^5.9.3",
+   "typescript": "^7.0.2"
  }
}
```

Reinstall after changing it. `next build`'s own typecheck step and your app's own type-checking
will keep working. What you lose the moment you do this:

- `npm run lint` (or `eslint` directly) — fails immediately, since `eslint-config-next` cannot
  resolve a compatible `typescript-eslint`.
- Editor inline type errors, autocomplete, and go-to-definition for TypeScript files — your editor
  falls back to no language intelligence for `.ts`/`.tsx` files, or errors trying to start the
  TypeScript server.

If you hit either of those and want them back, pin `typescript` back to `^5.9.3` and reinstall —
nothing else about your app changes either way.
