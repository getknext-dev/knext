> **Honest, evidence-gated status of what the knext adapter supports.** Every row is grounded in
> real, on-disk evidence and a mechanical guard test fails CI if a ✅ ("supported") row cannot be
> backed up. When in doubt it is marked ⚠️, not ✅.

<Callout type="info">
**The official suite runs per runtime × builder cell — not one number.** knext builds and runs a
Next.js app more than one way (standalone on Node or Bun, built with Turbopack or webpack, or the
`vinext` build), and each combination is tracked separately rather than folded into a single "the suite is green" headline. The
most-verified cell overall is still the **Turbopack build on the Node runtime**, whose last
completed 14-night-eligible run observed **792 tests passed, 0 failed**, at Next.js v16.2.12 — the
prior credentialed ref, kept here for history. The default cell — Turbopack on the Bun runtime, the
compiled bytecode executable — and the two webpack cells each have a 792/0 run behind them at
that same prior ref. See [The official Next.js compatibility credential](/docs/compat-suite)
for what credentialing requires and where every cell currently stands.

A handful of upstream tests introduced between the two releases encode behaviour that only
Vercel's own hosting infrastructure produces (for example, a CDN cache header) rather than
anything a self-hosted deploy can or should reproduce; those are documented and excluded the same
way the architectural gaps below are, with their own evidence trail.
</Callout>

## Legend

| Marker | Meaning |
|---|---|
| ✅ | **Supported** — backed by a red-on-fail check (the per-PR `compat-smoke` gate) or test-covered source on disk. |
| ⚠️ | **Partial** — implemented but **not** guarded by a hard correctness check, or with a known caveat. Do not rely on it as "verified." |
| ❌ | **Unsupported / unverified** — no working implementation or no evidence; treat as a gap. |
| ⛔ | **Upstream-gated** — architecturally out of reach today (global edge, not yet adapter-standardizable upstream). |

The `compat-smoke` job runs per-PR on a **Node + Bun** matrix. It is a knext **smoke** gate, not the
official suite.

## v1.0 credentialing

A green suite run is evidence for a cell; it is not the same claim as **v1.0-credentialed**. Each
of the four v1.0 cells (Node and Bun, each on Turbopack and on webpack) must independently bank 14
consecutive scheduled nights, run against a frozen release build of knext (not the fast-moving main
branch), before it counts toward v1.0. The `vinext` cells are outside the credential and stay Beta. Main
nightlies keep running as an early-warning signal and can flip a row back to ❌ on a regression, but
they never advance a cell's credential count. No cell is credentialed today. Full detail:
[the compatibility credential](/docs/compat-suite).

## Maintenance & honesty

- **Every ✅ is mechanically gated.** In the knext source repository, a guard test parses this
  table's canonical twin and fails CI if a ✅ row's evidence does not resolve to real on-disk
  files, a hard `compat-smoke` check, or a recorded green run.
- **The official-suite claims are revocable, not permanent.** Each cell's ✅ or ⚠️ is backed by the
  most recently cited run; a shard with any failed test fails the job, a red scheduled run raises an
  alarm, and the policy is to flip the affected row back and withdraw the claim.
