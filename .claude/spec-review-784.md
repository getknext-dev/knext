## Issues found

**A. Criterion 1's "attached per image" is satisfied as a CI artifact, not as ADR-0042 C6's cosign attestation — and the gap is not recorded as still-owed.**
C6 is explicit: SBOM "attached as a **cosign attestation**". This PR attaches a per-`github.sha` Actions artifact. That is defensible today (no vinext image is published, so there is no image digest to attest), and the PR/threat-model do state that no publish lane exists — but neither states that the *attestation* half of C6 remains outstanding. Consequence: the `needs`-scan durability argument covers **ordering** only. A future publish lane inheriting `needs: vinext-precompile-closure` passes `tests/precompile-closure-gate-ci.test.ts` while publishing an image with **no SBOM attached to it** — the exact half of C6 that no guard covers. Ask: one sentence in `docs/security/threat-model.md` (and ideally the ci.yml comment) recording "cosign attestation of the closure SBOM onto the vinext image digest is owed the day a publish lane ships", so it is found rather than remembered.

**B. The precondition is discoverable from CI, not from where the inlining lands.** Nothing in `examples/bun-exec/vite.config.ts` or ADR-0042 tells an author of the `noExternal: true` change *why* the gate exists; ADR-0042:158 still reads "Re-open only if the scan gate is first re-established against the pre-compile closure" without noting that it now has been. Low severity — the gate cannot be evaded, since it runs unconditionally — but a stale ADR line is how the next reader concludes the obligation is unbuilt. Ask: a one-line "(built: `vinext-precompile-closure`, #764)" marker on ADR-0042 C6 / :158.

**C. Scope note (not a criterion miss).** The gate covers exactly one closure — `examples/bun-exec`. That is the only vinext app in-repo, so this is the right subject today; but the shipping story for a *user* app on the vinext target has no equivalent closure gate. Worth naming in the threat-model rather than leaving it implied by "the closure".

## Verdict

**ISSUES_FOUND** — all three acceptance criteria are met by tested behaviour and "Closes #764" is honest; the objections are documentation-of-residual-obligation, not missing function. Issue **A** is the one that matters (a durable gap C6 names and no guard covers). B and C are one-line doc fixes. None require code changes; if the lead prefers, A/B can land as a follow-up docs commit on this branch rather than blocking merge.
