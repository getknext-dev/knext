# W2 · Failure surface inventory — runtime, operator, CLI

> Wayfinder ticket [#590](https://github.com/getknext-dev/knext/issues/590), child of map #588.
> **Inventory only** — no fixes proposed, no ranking implied by row order.
>
> **Scope:** `packages/kn-next/src/adapters` (runtime incl. `node-server.ts`),
> `packages/kn-next-operator` (Go operator), `packages/kn-next/src/cli` (CLI).
> CI gates/workflows, the docs site, and release plumbing are out of scope — see the
> last section.
>
> **Method note on the "detecting" column.** A test that exercises the *module* is not a
> detector for *the module being absent from the shipped bundle*. A guard that passes by
> skipping is not a detector. A test that injects a fake is not a detector for the
> production implementation. Rows are marked accordingly, per the project's own standard
> (`.claude/rules/workflow.md`, "a guard that stays green when its subject is removed is
> decoration").
>
> Where `CLAUDE.md` and other docs disagree, CLAUDE.md wins — except where the tree
> contradicts CLAUDE.md, in which case the tree wins and the staleness is flagged in the
> row. Two such cases are noted (R22, O8).

## Rows with real evidence and **no detector at all**

These are the ones where a change could break the behaviour and no test, guard, or condition would go red. Listed for completeness, not ranked.

- **O1** — `DefaultCleaner.CleanupStorage` no-ops on `gcs`/`azure`; zero tests touch the production cleaner.
- **O2** — `Cleaner` wiring is one unasserted line in `main.go`.
- **R1** — signal-killed child → supervisor exit 0.
- **R9** — generated-app seam-alive guard green-by-skip *(a guard exists; it is decoration on that path)*.
- **R10** — compile-cache-shadow step can be dropped from the bundle unnoticed.
- **C1 / C2** — non-CLI and shimmed apply paths silently prune CR fields.
- **R2 / R3** — preload absence degrades to a warn with nothing asserting bundle presence.
- **O4** — CLI quantity regex vs Go `ParseQuantity` equivalence unasserted.
- **C5** — orphaned image tag on the symmetric partial-deploy leg.
- **R8** — `next dev` edge-fence behaviour unverified and unpinned.

## Corrections to standing docs found while inventorying

Recorded because `CLAUDE.md` is the tiebreaker document and two of its notes no longer match the tree.

1. **`CLAUDE.md` §4 — the #314 schema-diff preflight is described as "the complete fix… still open". It is shipped.** `packages/kn-next/src/cli/schema/` contains `preflight.ts` (388 lines), `crd-schema.ts`, a *scanned* (never enumerated) `emitted-fields.generated.ts`, and a staleness gate at `__tests__/cr-fields-generated.test.ts`. It runs in `deploy.ts:285` **before any side effect** and as doctor's `crd-schema` check. The residual gaps are narrower than the note implies — see C1, C2, C4.
2. **[#471](https://github.com/getknext-dev/knext/issues/471) item 3 — "digest-pin the busybox helper image (currently tag-pinned `busybox:1.36.1`)" is resolved in the tree.** `internal/controller/image_prewarm.go:70` reads `busybox:1.36.1@sha256:73aaf090f3d85aa34ee199857f03fa3a95c8ede2ffd4cc2cdb5b94e566b11662`, with a bump procedure in the comment at :69.
3. **`CLAUDE.md` §4 — "`doctor` checks only that the CRD *exists*, not that its schema covers what the CLI emits" is stale** for the same reason as (1): `doctor.ts:558-587` compares `EMITTED_CR_FIELD_PATHS` against the installed CRD and hard-FAILs on any gap.
